# AGENTS.md — kbTrainer 2.1, Electron edition

Read this before changing anything. `PLAN.md` holds the staged migration
history; this file holds the rules and the map.

## Rule #1 — ask first

If a change is not clearly requested, or you are unsure how it interacts
with the era code, stop and ask. Do not commit, push, or otherwise mutate
git — the owner does all git.

## Experiments live in `/code/experiments` — never in `/tmp`

Every experimental, probe or throwaway script (live CDP/strategy probes,
trace dumps, logs, screenshots, backups) goes into
`/code/experiments/<YYYY-MM-DD>-<topic>/` with a short `README.md` (question,
how to run, result) — never `/tmp`, never a tool's session scratchpad, even
if the tool says so. Experiments are kept; never delete them. (Same rule in
`/code/AGENTS.md`.)

## What this is

The 2010 kbTrainer touch-typing trainer (HTA), ported to Electron and
migrated in stages: the era renderer (`app/`, vanilla JS with `with(user)`,
implicit globals, a script loader) keeps running while typed TypeScript and
Vue 3 islands replace it piece by piece. The domain runs on
[mnemonica](https://www.npmjs.com/package/mnemonica): every key press
constructs a chain of instances, streamed live to Mnemonica Graphica.

**The typing path is a live demo** (construction speed vs. the live-trace
channel). `KeyStroke → Correct | Mistake → StatUpdate → LetterPick |
WordPick → KeyLight` must keep working and keep streaming — `SMOKE-TRACE`
and `SMOKE-CURSOR` in the smoke run prove it.

## Commands

```sh
npm run build      # typecheck (runs tactica first) + every compile step
npm test           # vitest — run `npm run build` first, see "Traps"
npm run lint       # eslint over the era sources in app/bin
npm run smoke      # build + full Electron e2e under xvfb, ends in SMOKE-OK
npm start          # run the app
npm run start:strat    # the app + the strategy channel (USE_STRATEGY=1)
npm run start:jaegger  # a local Jaeger (scripts/jaegger.sh) + the app exporting spans
npm run start:strat:jaegger  # both: Jaeger + spans + the strategy channel
```

A change is done when `build`, `test`, `lint` and `smoke` all pass.

## Map

| Path | What it is |
|---|---|
| `app/` | the era renderer. `app/bin/*.js` era sources, EXCEPT the compiled outputs listed in `eslint.config.mjs` `ignores` — never hand-edit those |
| `src/renderer/*.ts` | typed renderer code (engine, layouts, skins, Vue islands), compiled into `app/bin/` |
| `src/main.ts`, `src/preload.ts` | the Electron shell. The preload boots the domain: topologica over `models/`, otel `attachHooks`, the strategy channel |
| `src/domain/` | `store.ts` (boot + era interop), `collection.ts` (the typed collection), `loadTopology.ts` (topologica replay for tests) |
| `models/` | the mnemonica types as a folder trie — one folder per type, `index.ts` exports the constructor handler |
| `models/chain.ts` | lowercase on purpose (topologica skips it): the typed views of ancestors that handlers read via `utils.parent` |
| `.tactica/` | generated by `npm run tactica`; committed so Mnemographica works from a fresh clone. Never hand-edit |
| `tests/` | vitest unit tests; `src/smoke.ts` is the e2e harness |

## mnemonica rules for this project

- **Model files export raw handlers**, not types — topologica passes them
  into `define()`. Never import a model file to construct something.
- Roots come from the collection: `collection.lookup('Program')` (see
  `store.ts`). Everything else is built from a parent instance:
  `new kbstore.session.KeyStroke(key)`, then `new keystroke.Correct()`.
- Handlers reach ancestors with `utils.parent(this, 'Session')` and narrow
  it to a view from `models/chain.ts` — the one tolerated cast, because
  `utils.parent` returns `object | undefined`. Keep the views in
  `chain.ts` in sync with the handlers.
- The collection runs with `blockErrors: false` (see `collection.ts`): a
  throwing constructor throws a plain error instead of poisoning the
  session chain.
- After changing a model, run `npm run build` (it regenerates `.tactica/`)
  and check `.tactica/hierarchy.txt`.

## What is live

Constructed by the running app today, and where:

| Types | Wired in |
|---|---|
| `Program` (+ `UserProfile`), `Session` (+ `EventHandler`), `Timer` → `Tick` | `store.ts` boot, the per-second clock |
| `Run` → `Lesson` \| `Book` → `Native` \| `Paragraph` (+ `KeyLight`), one per lesson/book start and per repeat after the end of the text; `Finish` when the text is done | `engine.ts` `runStart` / `runRepeat` |
| `KeyStroke` → `Correct` → `StatUpdate` → `LetterPick` \| `WordPick` (+ `KeyLight`), `KeyStroke` → `Mistake` → `StatUpdate` (+ `KeyFlash`), `RunControl` → `Pause` \| `Resume` \| `Quit` | `engine.ts`, `snk.js` |
| `RunControl` → `LessonPrev` \| `LessonNext` \| `BaseNext` (Ctrl+←/→ lesson, Ctrl+↑/↓ base, lesson mode; records the lesson the era moved to, its restart then builds the new `Run`) | `engine.ts` `mooving_keys` |
| `ViewControl` → `ZoomIn` \| `ZoomOut`, `WindowState` | `preload.ts` |
| `Log` (one per loader-log line) | `loader.js` |
| `BookMark` (the typing position saved into a book — before the mode and library dialogs, and on window close; book runs only) | `kernel.js` `saveCurrentBookPosition` |
| `ModeF1` (help), `ModeF3` (typing mode), `ModeF7` (stats reset), `ModeF12` (loader log) | `snk.js` |
| `ModeF2` (map switch — only a real switch, not the boot activation) | `kb.js` `changeMap` |
| `ModeF4` → `ModeDialog` → `ModeSet` \| `LessonPick` \| `BookPick` (selections; the run starts when the dialog closes) | `snk.js` + `modeIsland.ts` |
| `ModeF5` → `SettingsDialog` → `PrefSet` \| `MapsPairSet` \| `SkinPreview` | `snk.js` + `setsIsland.ts` |
| `ModeF8` → `LibDialog` → `BookSelect` \| `BookImport` \| `BookDeleteRequest` → `BookDeleted` | `snk.js` + `libIsland.ts` |
| `FileDialog` → `FilePick` (the native file selector, over the library) | `libIsland.ts` |

`SMOKE-DLG-CHAIN`, `SMOKE-F7` and `SMOKE-CURSOR` check them in the e2e run.

**The domain owns the cursor.** `runStart` turns `vars.strArr.pos` into a
view onto `session.run.pos`: a correct key moves it only through the chain
(`StatUpdate` → `LetterPick`|`WordPick`), and every other era cursor move —
backspace, the space and non-typable skips, Home/End and the book jumps,
the end of the text — writes the same cell through the view. A book's run
starts at its bookmark. The lesson timer (`stats.timerCnt`) stays the
engine's (`app.counter()` knows when typing is really going on); `Tick`
only reads it. `Run` does not reset the stats: the era keeps them across
restarts and repeats; only the first start and F7 zero them.

**One key press, in order.** The engine's key handler (`app.mooving_keys`)
is `dive.wrap`ped with the session (`window.kbDive`, from the preload), so
every key press is one dive call edge. `Correct`|`Mistake` queue their
`StatUpdate` with `queueMicrotask` — it is built on committed data, after
its parent has finished, so dive parents it on `Correct`|`Mistake` (built
inside the constructor it had no parent edge yet). The redraw is the
RESULT of the stat update: a collection `postCreation` hook on
`StatUpdate` calls `app.p_go()` (`app.statUpdated`), so keydown itself does
not redraw a typed key. Microtasks drain before the next key event, so the
order per key is fixed: `Correct` → `StatUpdate` → `LetterPick`|`WordPick`
→ redraw. Tests that type keys `await` the same drain (`type()` / `settle()`).

How the wiring is done — keep to it:

- Every construction the era code makes is wrapped in `try{ … }catch(e){}`
  (TS: the `kbZoomEvent` pattern in `preload.ts`): the feature must keep
  working even if the domain failed to boot.
- The models RECORD what the era code just did: they are constructed right
  after the era write, and where they write, they write the same value into
  the same cell (`adoptUser`'s accessors), so nothing competes. `PrefSet`
  gets the canonical profile name — `kbstore.userAliases` maps the four
  era names that differ (`errMode` → `errorControl`, …).
- A dialog's domain instance travels to its island as
  `dialogArguments.domain` (plus `dialogArguments.kbstore` where the page
  needs the program); the island constructs its actions on it.
- `program.library` is synced from the disk list in the library dialog's
  `loader()` — a data sync, not an action.

Not constructed live, and why:

- **No counterpart in the app:** `DirList` (the native selector lists no
  directories for the app).
- **No counterpart in the era either:** `Vocabulary` (the era's vocabulary
  mode is a stub; the model throws "not implemented").
- `EventHandler.dispatchKey` is never called: the era `snk.js` routes the
  keys itself. The tests drive the models through it.

Known era quirk, left as is: F12's `loader_log_view()()` — the first call
opens the log window and returns `undefined`, the second `()` then throws
a `TypeError` in the key handler. `ModeF12` is recorded before it.

## Probe the running app

```sh
npm run start:strat        # = USE_STRATEGY=1 electron .
```

With `USE_STRATEGY=1` the preload hosts a `@mnemonica/strategy` channel
(without it there is none — a regular user never gets a WS server). Its
host, port and token are in the log, in a thin line under the keyboard
(`fit.js` keeps that band free — `kbFitReserveBottom`), and in
`app/strategy-channel.json`, which mnemographica's App Channel reads. The
smoke run sets the flag itself. Answer runtime questions against the live
session instead of from the source:

```js
const { WSSession } = require('@mnemonica/strategy');
const { port, token } = require('./app/strategy-channel.json');
const sess = await WSSession.connect('127.0.0.1', port, token);
await sess.request('eval', { expression: 'window.kbstore.session.stats' });
sess.setNotificationHandler('trace', (p) => console.log(p.edges));
await sess.request('traceSubscribe', {});   // live construction edges
```

Headless: `USE_STRATEGY=1 xvfb-run -a -s "-screen 0 1920x1280x24" npx electron .`.
There is no per-file reload yet — restart the app after editing sources.
The app saves the profile (`~/.config/kbtrainer-electron/user.txt`) on
close: back it up before live probing and restore it afterwards.

## Jaeger (talk / demo mode)

```sh
npm run start:jaegger          # Jaeger + the app exporting spans
npm run start:strat:jaegger    # … plus the strategy channel
```

`scripts/jaegger.sh` runs the `jaeger-mnem` container (UI on :16686, OTLP
HTTP on :4318) with the local `scripts/jaeger-v2.yaml` and
`scripts/jaeger-ui.json`. The name and ports are shared with the
tactica-nestjs demo: a running `jaeger-mnem` is reused as is (its traces
survive), a stopped one is replaced. The app then starts with
`OTEL_EXPORTER_OTLP_ENDPOINT=http://localhost:4318`.

With the variable set, the preload attaches `@mnemonica/otel`'s
`DiveOtelProvider`: it subscribes to the dive edges `attachHooks` feeds —
one span per construction (`dive.create:X`) and per wrapped call
(`dive.call:keystroke:mooving_keys`), service `kbtrainer` — and publishes
edge id → trace id, so the strategy channel's Live Trace edges carry their
Jaeger trace. Without the variable no OTel SDK is loaded at all.

Trace shape today: a key press is a trace rooted at its call edge with
`KeyStroke` under it. `Correct`, `StatUpdate` and `LetterPick` are
parented in dive on edges that have already finished, and
`DiveOtelProvider` looks parents up among OPEN spans only, so in Jaeger
they start traces of their own. dive's own tree (Live Trace, `getFlow`)
is complete.

The exporter is a small OTLP/JSON sender over Node's `http` module, not
the stock `exporter-trace-otlp-http`: Electron strips `Buffer`, `process`
and `setImmediate` from the page once the preload returns, and the stock
exporter's send path fails with `Buffer is not defined`.
`window.__kbOtel` is the tracer provider (`forceFlush()` over the probe
channel).

## Traps

- **Build before testing.** `tsc -p tsconfig.renderer.json` and
  `tsconfig.emit.json` emit `.js` next to `src/domain/*.ts`,
  `models/chain.ts` and `.tactica/types.ts` (files outside their
  `rootDir`), and those `.js` files are tracked. Vite resolves `.js` before
  `.ts`, so testing without a build may run the previous code.
- Every build rewrites `generatedAt` in `.tactica/*.json` — expected noise.
- `app/strategy-channel.json` is written by the running app (with
  `USE_STRATEGY=1`) for channel discovery; it is not source. A run without
  the flag deletes a leftover one.
